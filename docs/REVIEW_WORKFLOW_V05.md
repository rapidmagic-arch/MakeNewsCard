# MakeNewsCard v0.5 — 기사 검토 작업대 개편·영향도·자체 검증

## 목적(유지)

**회차별 수집 원본 → GPT·규칙 분류 제안 → 담당자 추천/예외 선택 → 선택 기사 편집 → 892호 HTML 미리보기/회차 확정**을 최소 조작으로 수행한다. 외부 발송·운영 배포는 수행하지 않는다.

## 수행 체크리스트 (2026-11-23 기준)

- [x] **P0-1 회차별 기준**: `runs.edition_id` 증분 마이그레이션·신규 수집 귀속; 화면의 수집 기록은 현재 회차만 집계. 기존 귀속 불가 기록은 NULL 보존.
- [x] **P0-1 날짜 미확인**: 전역 미확인 원본을 모든 회차에 자동 편입하는 동작 제거. 새 수집에서 실제 관찰된 원본 ID만 해당 회차의 검토 대상으로 연결하고 `undated_count` 표시.
- [x] **P0-2 승인 경계**: GPT·규칙 분류와 요약은 제안 필드에만 저장. 승인된 `section_override`, `summary_override` 또는 원본만 HTML 출력에 반영. 오래된 분석 해시 및 다른 회차 JSON 가져오기 차단.
- [x] **P0-2 TOP**: 신규 회차에서 TOP을 자동 체크하지 않음. 기존 TOP 선정은 그대로 보존. TOP 선정·본문 수록은 별도 결정.
- [x] **P0-3 식약처**: 진짜 `mandatory`인 자료는 제외 불가. 일반 식약처 자료는 담당자가 제외할 수 있으나 자동 제외하지 않음. 동일 `m_<board>/view.do?seq=<id>`는 식약처 섹션 전체에 1회 출력(원본 레코드 삭제 없음).
- [x] **P1-1 추천 작업대**: 추천·추가 검토·그 외·수록 목록·전체 탭; 12건 페이지, 검색/출처/분야 필터. 일반 규칙 추천과 GPT 제안 출처를 따로 표시.
- [x] **P1-2 일괄 작업**: 선택 ID를 페이지 간 유지, 선택 수록/제외(명시적 적용 시 기존 선택 변경 가능)·추천 분야 반영·분야 추천 전체 일괄 수록. 각 작업의 적용 범위 명시 및 확인.
- [x] **P1-3 상세 편집**: 원본 / GPT 제안 / 최종 발행 내용을 별도 표시. GPT 요약은 선택 기사 상세란에 복사만 하며 저장을 눌러야 반영. 미저장 입력값 보존·이동 전 확인.
- [x] **P1-4 HTML 출력**: 892호 템플릿 구조 유지, 미리보기는 내부 운영 경고 없이 발행물 콘텐츠 기준, 최종본 확정 스냅샷 불변. 식약처 상세 목록 중복 제거·간격 정리. TOP 요약은 임의 절삭하지 않고 편집란에서 220자 초과 경고.
- [x] **UX 검증**: 모의 208건(언론 171/식약처 37) 대기열·13건 2페이지 선택·선택 적용·상세 문구 저장, 데스크톱/모바일 확인.
- [x] **회귀 검증**: pytest 38개, 기존 자료 수집 및 UI 스모크 테스트, JS 문법 검사.

## 의존성 및 영향

| 변경 | 영향 영역 | 보존/검증 포인트 |
|---|---|---|
| 회차별 수집 이력 | DB `runs`, 수집기, HTTP 응답, 대시보드 | 기존 이력 NULL 귀속 보존; 동일 기간 별도 회차 혼동 방지 |
| 날짜 미확인 원본 | `prepare`, 수집 실행, 편집 후보 | 새 수집의 실제 출처 ID로만 편입, 임의 전역 편입 금지 |
| GPT 승인 경계 | JSON 가져오기, 일괄 반영, 렌더러 | 제안만으로 수록/섹션/요약 변경 불가 |
| TOP 자동 체크 중지 | `prepare`, 새 회차, 기존 테스트 | 과거 TOP 선택 보존; 신규 회차는 사람의 명시적 선택 |
| 식약처 수록 범위 | `update_decision`, HTML | `mandatory=1` 보호; 일반 문서의 수동 제외 허용, 자동 제외 없음 |
| 추천 작업대 UI | `editor.html`, 전용 `editor.css` | 사용자가 추천을 일괄 반영하거나 예외를 찾는 작업 흐름 |
| 발행 미리보기 | `render`, `/preview/html` | 관리자 경고문 제외, 읽기용 표현; 기존 확정본 HTML 보존 |

## 확인된 한계·미반영

- 실제 Windows SQLite 데이터 208건의 날짜/내용·출처·중복·관련성은 원문 실증을 하지 못했다.
- 식약처/언론사 **전수 확보 및 사이트 메뉴 자동 탐색**은 이번 UX 개편 범위 밖이다. 기존 수집기는 `partial`과 검증되지 않은 페이지 범위를 구별한다.
- GPT API 실호출 및 비용·모델 품질 검증은 미수행. `OPENAI_API_KEY`가 없으면 기존 JSON 가져오기/내보내기 흐름 이용.
- 지난 버전에서 회차 ID 없이 기록된 `runs` 행은 소급 귀속하지 않았다. 과거 선택된 TOP은 수동 선정/규칙 초기 선정의 출처를 완전히 복원할 수 없다.
- 이메일 발송용 브랜드 로고·연락처·수신거부 설정은 자동 생성하지 않았다. 메일 발송 없음.
- 892호 원본의 전체 정보·법정 고지/의무 수록 자료를 임의로 요약/제외하지 않았다. **TOP 요약 220자는 화면 권장값이지 서버 차단·콘텐츠 자르기 규칙이 아니다.**

## 수동 확인 동선

1. Windows DB 백업 후 작업 브랜치를 실행해 주차/회차를 선택한다.
2. `자료 수집`을 같은 회차에서 2회 이상 실행하여 신규/중복 후보 숫자와 회차별 수집 이력을 확인한다.
3. `기사 검토`에서 추천·추가 검토·그 외·수록 목록 탭을 각각 확인한다.
4. 추천 전체 적용 또는 여러 페이지에 걸쳐 선택한 기사만 수록하고, **사용자가 수동 제외한 항목 보호**를 확인한다.
5. GPT 미연결일 때 JSON 대체 경로가 보이고, JSON 가져오기 뒤에도 최종 수록은 사람의 버튼을 통해 이루어지는지 확인한다.
6. 기사 하나를 열어 원본 제목·GPT 제안과 최종 제목·요약·분야를 구분하고 저장한다. 미저장 상태 이동 전 확인을 점검한다.
7. 미리보기 HTML의 식약처 섹션 간 중복, 빈 섹션, TOP 요약 길이, 이메일 클라이언트 레이아웃을 확인한다.
8. 내용 확정 후 수정 API 차단, 확정 스냅샷 HTML 해시 일치 여부를 확인한다.
