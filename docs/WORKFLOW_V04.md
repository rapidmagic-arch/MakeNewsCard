# MakeNewsCard v0.4 업무 구조 및 적용 경계

## 실제 워크플로

대시보드 → 자료 수집 → 기사 검토·편집 → 미리보기·확정 → HTML 다운로드. 환경설정은 조회 화면으로 분리.

- 자료 주차는 **수집 기간**의 속성이다. 기간이 월요일~일요일이면 ISO 연도·주차 `YYYY-Www`; 다른 기간은 사용자 지정 범위로 표시.
- 뉴스레터 **회차**는 발행물을 의미하며, 주차와 동일한 개념이 아니다. 같은 주차에도 다른 `edition_id`를 만들어 특별호 작성 가능.
- 확정 시점(`confirmed_at`, UTC), 담당자 입력값(`confirmed_by`), 선택 회차번호(`issue_number`)를 기록.
- `draft → confirmed`만 영속 상태로 사용하며, 수집/AI 분석 진행은 개별 작업 상태로 관리. 실제 메일 발송은 범위 밖.
- 확정은 기사 편집 결과·원본 필드 및 최종 HTML을 단일 트랜잭션에서 별도 `edition_confirmations` 스냅샷으로 저장. SHA256 포함.
- 확정 뒤에는 개별 편집, 일괄 수록, GPT 결과 저장, TOP 수정, 추천 재계산 및 해당 회차 수집을 차단. 일반 CLI 수집기는 다른 회차 원본에 영향을 줄 수 있지만 **확정 스냅샷에는 영향이 없다**.
- 확정 후 변경은 **별도 새 회차**에서 수행. 확정 취소·기존 확정본 덮어쓰기는 제공하지 않음.
- 메일 발송용 수신거부·발송 시스템 설정은 아직 연결되지 않음. 확정 HTML은 편집 결과의 보존본이며 실제 발송 완료나 발송 준비 완료를 보증하지 않음.

## GPT 실행 및 검토

- `OPENAI_API_KEY`가 있을 때만 웹의 명시적 GPT 분석 버튼 또는 `main.py ai-review`가 OpenAI Responses API를 호출. API 키는 브라우저와 SQLite에 기록하지 않음.
- API 미설정 시 기존 JSON 내보내기·가져오기 방식 사용. 규칙 기반 추천은 GPT 검증이 아님.
- 분석 입력은 해당 회차의 **제목·목록 URL·날짜·저장된 요약 등 메타데이터**. 원문 전체를 크롤링하거나 사실 확인했다고 주장하지 않음.
- 분석 단위당 최대 20건, API 비용과 외부 데이터 전송은 사용자가 실행 버튼을 누를 때에만 발생.
- API 응답은 스키마 및 입력 기사 ID를 검증하고 `decisions`의 제안 필드에만 저장. 사람의 상세 수록 여부, 제목/요약 수동 편집을 덮어쓰지 않음.
- 검토 질문창은 **선택한 최대 10건**에 대한 단발성 질의/답변. 대화 세션 기억, DB 직접 수정, 자동 재질문 에이전트는 미구현.
- HTML 확정본에는 담당자 미승인 AI 요약을 포함하지 않음. 사람의 `summary_override` 저장이 승인 표현으로 사용됨.

## 설정 및 UI

- `editor.html` 앱 셸은 5개 업무 탭을 사용하고 기사 목록은 12건 단위로 페이지 이동.
- `assets/editor.css`는 운영 UI 전용, `templates/892_slots_original.html`은 이메일 HTML 전용.
- 환경설정 화면은 현재 YAML 수집원과 키워드의 조회만 구현. 변경은 `config/sources.yaml`, `config/editorial.yaml`에서 해야 하며, UI 편집 저장 기능은 추가 설계 필요.
- 기존 `runs.status` (예: partial/failed)는 확정 상태와 별개로 유지. 수집 완료가 데이터 완전성을 입증하지 않음.

## 검증 경계

- 기존 API 및 편집기 테스트 + 회차/확정·GPT 모의 API 테스트.
- 브라우저는 정책상 로컬 HTTP 네비게이션이 차단되어 HTML/Fetch 모의 실행으로 화면 전환·170건 필터·모바일 확인.
- 실제 MFDS/언론, OpenAI 유료 API, Windows 실사용 DB, Outlook/메일 발송 호환성은 이 환경에서 실증하지 않음.
