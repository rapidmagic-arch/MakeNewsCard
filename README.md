# MEDiTIP 뉴스레터 독립형 MVP (v0.2 개발 브랜치)

## 실제 구현 범위

- 별도 AI 없이 실행되는 **공개 RSS/목록 메타데이터 수집 어댑터**, 원본·변경 버전·실행 상태를 저장하는 SQLite
- 기존 892호 메일을 기반으로 한 HTML 템플릿 재사용 (로고·배너는 재연결 대기 표시)
- **동적 TOP 뉴스 건수**, 섹션별 목록, 수록 여부·순위·제목·요약을 수정하고 SQLite에 저장하는 로컬 웹 UI
- 규칙 기반 1차 추천(명시적으로 AI와 구분), 외부 ChatGPT가 분석한 JSON 제안 가져오기
- 이전 2차 테스트(7건) JSON으로 검증 가능한 재현용 샘플
- 발송 기능 **없음**. 원본 뉴스레터의 개인정보·개인화 추적링크는 포함하지 않음.

## Windows 실행

Python 3.10 이상 설치 후, 폴더에서 `start_windows.cmd` 실행. 설치가 끝나면 브라우저에 **http://127.0.0.1:8765/** 를 연다. 명령행으로 직접 하려면:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py init
.\.venv\Scripts\python.exe main.py seed-demo
.\.venv\Scripts\python.exe main.py serve
```

샘플 대신 새 회차를 만들 수 있다:

```powershell
.\.venv\Scripts\python.exe main.py edition w2026-48 --start 2026-11-23 --end 2026-11-29 --target 4
.\.venv\Scripts\python.exe main.py prepare w2026-48
.\.venv\Scripts\python.exe main.py serve --edition w2026-48
```

## 웹 화면에서 실제 자료 수집 (v0.2)

`start_windows.cmd`로 실행한 뒤 상단 **실제 자료 수집** 영역을 사용한다.

1. **시작일/종료일**을 확인한다. 현재 회차 기간과 다르면 **이 기간으로 회차 생성·전환**을 먼저 누른다. 회차 전환 시 기존 회차 편집 내용은 SQLite에 그대로 남는다.
2. 식약처 등 **수집 사이트**를 선택하고 **공개 목록** 또는 (RSS ID가 설정된 식약처에 한해) **RSS**를 고른다. 목록 최대 조회 페이지를 1~10 사이에서 정한다. 최초 시험은 `press` 1곳, 1~2페이지를 권장한다.
3. 언론사를 선택했다면 **해당 사이트의 접근·이용 조건을 직접 확인**하고 확인란을 체크한다. 이용 제한 우회는 지원하지 않는다.
4. **선택한 사이트 실제 수집 시작** 버튼을 누른다. 서버가 사이트별로 순차 실행하고 **진행 건수·페이지 수·부분/실패 상태**를 표시한다. 수집 중에도 편집 화면은 사용할 수 있다.
5. 수집 작업 종료 후 회차 후보 목록을 갱신한다. 수집 자료와 수집 이력은 SQLite에 저장되며, 기존 편집 결정을 덮어쓰지 않는다.

**주의:** 현재 RSS는 신규 후보 발견에 가깝고, 공개 목록은 게시판 완전성 검증 전이므로 실행 종료 후에도 `partial`일 수 있다. `failed` 및 0건은 구별해 확인한다. HTML 발송 기능은 없다. 웹 UI는 `127.0.0.1:8765`에서만 동작한다.

로컬 API는 설정된 출처만 허용하며, 실행 요청에는 동일 출처 토큰이 필요하다. 하나의 수집 작업만 동시에 실행한다. 웹 수집은 네트워크가 연결된 Windows PC에서 실제 사이트별로 시험해야 한다.

## 출처 수집 실행

`config/sources.yaml`에서 각 사이트·섹션·RSS 후보를 관리한다. `config/editorial.yaml`에서 섹션별 규칙 점수와 관심 키워드를 변경하고 `prepare`로 점수를 갱신한다. 기존 담당자 선택은 덮어쓰지 않는다. **수집 전 해당 사이트 이용조건과 접근 가능성을 확인**한다. 다음은 실제 시도하는 명령이며 테스트 환경에서는 외부 DNS 연결이 제한돼 실행 성공하지 못했다.

```powershell
.\.venv\Scripts\python.exe main.py collect --source press --method rss --start 2026-11-16 --end 2026-11-22
.\.venv\Scripts\python.exe main.py collect --source press --method board --start 2026-11-16 --end 2026-11-22 --max-pages 3
.\.venv\Scripts\python.exe main.py prepare w2026-48
```

RSS는 **신규 후보 발견**, 공개 목록은 **부분 수집**만 구현한 상태이며, 8개 식약처 게시판의 페이지네이션/목록 구조는 실제 사이트에서 실증하지 않았으므로 자동으로 `complete` 처리하지 않는다. 언론사도 첫 페이지 링크 메타데이터를 대상으로 하며 기사 원문 대량 수집은 하지 않는다.

**미구현 / 추가 실증 필요:** 의약품안전나라 최초·변경승인과 치료목적 사용승인의 모든 이벤트 공식 API/엑셀 커버리지, 의약품 주간 허가 데이터 표, 각 게시판 완전성 검사, 원문 첨부 파싱, 다이렉트센드 발송, ChatGPT 개인 계정의 로컬 DB 자동 직접 호출. 관련 사이트별 수집 전략은 `config/sources.yaml` 및 앞서 작성된 별도 설계 문서를 참고한다.

## 승인정보 CSV 가져오기 (수동 파일 경로)

공식 조회/엑셀 자료를 담당자가 CSV UTF-8 또는 CP949로 저장한 경우 다음을 사용할 수 있다. 데이터의 원본성과 누락 여부는 **별도 검증**해야 한다. 5개 임상시험 필드는 요청한 형태로 HTML 표에 들어간다.

```powershell
.\.venv\Scripts\python.exe main.py import-approval-csv .\approvals.csv --kind clinical
.\.venv\Scripts\python.exe main.py prepare demo-2026-11-16-22
.\.venv\Scripts\python.exe main.py export-html demo-2026-11-16-22
```

`--kind`는 `clinical`, `treatment`, `drug` 중 선택한다. 변경승인 여부 등 CSV의 개별 이벤트는 별도 레코드로 저장하되, 자동 공식 사이트 다운로드를 구현했다는 뜻은 아니다.

## 웹 수집 오류(HTTP 400) 해결

- 수집 시작일·종료일이 상단 **현재 편집 회차**의 날짜 범위와 다르면 **[이 기간으로 회차 생성·전환]**을 먼저 실행한다. 편집 화면은 요청을 보내기 전에 이를 안내하며 기존 회차 데이터를 삭제하지 않는다.
- **식약처 전체 선택 + RSS**는 일부 게시판의 RSS 연결이 확인되지 않아 지원되지 않는다. 전체 게시판을 대상으로 시도할 때는 **공개 목록**을 선택한다. RSS는 설정된 식약처 출처만 선택한다.
- 언론사 사이트를 선택한 경우 공개 페이지의 이용조건을 확인하고 확인 체크박스를 선택해야 한다.
- 오류 문구는 **실제 자료 수집** 영역의 진행 상태 아래에 계속 표시된다. Chrome 개발자 도구의 Network → `/api/collect` → Response에는 서버가 돌려준 상세 오류가 있다.
- 수집 시작 후 각 출처의 `failed`/`partial`은 HTTP 400과 다른 상태이다. 실제 수집이 성공하거나 전체 수집이 확인되었다는 뜻은 아니다.

## 운영 유의사항

- SQLite DB 파일을 Git에 커밋하지 않는다.
- 로컬 서버는 `127.0.0.1`에만 바인딩되며, 상태 수정 요청에는 세션 토큰이 필요하다. 인터넷에 서버를 직접 공개하지 않는다.
- 자동 예약은 **Windows 작업 스케줄러에 수집 명령을 등록하는 방식**을 권고하며, 이 패키지는 스케줄을 자동 생성하지 않는다.
- 샘플 7건은 2026-11-16~22의 **일부 테스트 자료**다. 실제 전체 수집이나 원문 재검증을 뜻하지 않는다.
- TOP 선택과 식약처 상세 포함은 별도다. 원본 892호의 회사/임상/의약품 허가 영역은 정보가 없을 때 미수집을 숨기지 않도록 설계해야 하며 이 MVP에서는 임상 영역을 미연동으로 표시한다.

## v0.3 제미나이 수집 경로 의견의 선별 반영

- 식약처 게시판 수집은 기간 입력을 `srchFr`, `srchTo`에 함께 담아 요청하며, 실제 추출 결과의 날짜를 로컬에서도 검증한다. 서버 측 기간 필터의 실효성은 Windows 실사이트 검증 전까지 미확인이다.
- 식약처 동일 게시판·`seq`는 검색어/페이지 URL이 다르더라도 같은 수집 후보로 식별하고, 신규 수집 URL은 `view.do?seq=`로 정규화한다. 기존 SQLite 데이터와 담당자 편집 기록은 마이그레이션하거나 삭제하지 않는다.
- RSS 1:1 연결값이 설정된 식약처 게시판은 RSS에서 기간·게시판 ID가 일치하는 게시물과 목록 결과를 대조한다. RSS에만 발견된 게시물 수와 예시를 기록하며, RSS 누락/지연, 게시판 페이징 누락, 원문 수정 가능성을 구별해야 한다. RSS 검증 자체가 실패하면 본문 수집 결과를 폐기하지 않는다.
- RSS 제공 기간·게시판 전체 페이지 수·원문 첨부 확인은 **미실증**. 수집 완료(`complete`)를 자동 선언하지 않고 기존처럼 `partial`을 유지한다. 실제 0건과 실패를 구별한다.
- 식약처 공지(`m_74`), 공고(`m_76`)의 기존 올바른 매핑은 그대로 보존한다.
- 임상시험 `ST3`, 빈 `clinicStepCode`, 엑셀 POST, 제약 언론사별 URL 패턴 및 네이버 뉴스 교차검색은 제안에 불과하며 자동 수집 필수 규칙이나 구현 완료 항목으로 승격하지 않는다. 원문 API의 이벤트별 범위 확인 후 검토한다.

## v0.3: 언론기사 후보 분류·일괄 편집

- 기존 수집·저장 구조를 유지하며, 수집 기사의 제목과 제공된 요약을 **규칙 기반으로만** 분야별 추천한다. GPT 자동 호출은 구현하지 않았으며 제목 매칭은 원문 관련성 검증을 대신하지 않는다.
- `config/editorial.yaml`의 `industry_section_keywords`를 바꾸면 분야별 후보 판정 단어를 조정할 수 있다.
- 편집기에서 정책·시장·글로벌·연구개발·미분류별 후보/추천/수록 건수를 확인하고, 분야별 필터·추천만 보기·추천 일괄 수록·분야 일괄 적용·전체 수록/제외 기능을 사용할 수 있다.
- **수동 선택 보호:** `decisions.detail_reviewed`, `section_reviewed`를 SQLite에 증분 추가하고 개별 편집을 보호한다. 원본 `items`는 유지한다. 기존 수동 ON은 보호하며 기존 OFF는 초기 기본값과 수동 해제를 구분할 수 없어 확인 필요.
- 업로드 전 사용자가 GPT 분석을 수행하려면 **GPT 분석용 JSON 받기 → ChatGPT 분석 → GPT 분석 결과 JSON 가져오기**를 이용한다. 가져온 제안은 자동으로 수록되지 않으며 일괄 버튼 또는 개별 체크가 필요하다.
- 기존 관심 뉴스 TOP 체크와 **분야별 상세 수록 체크**는 서로 독립적이며, 필수 식약처 상세 수록 규칙은 바뀌지 않았다.


## v0.4: 업무 화면 분리 · 회차 확정 · 선택형 GPT 분석

- 웹 업무 메뉴를 대시보드 / 자료 수집 / 기사 검토·편집 / 미리보기·확정 / 환경설정 조회로 분리. 뉴스레터 HTML과 별도 `assets/editor.css` 적용.
- 기사 목록은 12건씩 페이지 전환; 원문·수록·TOP 편집은 기존 기능 유지. 사이트·분야 코드를 사용자용 한글 라벨로 표시.
- 회차의 자료 기간이 월~일이면 ISO 주차 `YYYY-Www` 표시, 그 외 사용자 지정 기간으로 표시. 같은 자료 주차에 여러 회차 ID 생성 가능. 발행 회차번호는 주차와 **별도로 입력**, 자동 계산하지 않음.
- 명시적 `최종 확정`: 현재 원본/사용자 선택 JSON 및 사용자 확인 요약만으로 생성한 최종 HTML을 `edition_confirmations`에 보존(SHA256 포함); `draft → confirmed`. 확정 이후 기존 회차 편집/API/수집 차단, 별도 회차로 후속 개정. **메일 발송은 하지 않음**.
- CLI: `python main.py issue-status <회차ID>`, `python main.py confirm <회차ID> --by "담당자" --number 893 --acknowledge`. 기본 API는 기존 로컬 8765 포트.
- 선택형 GPT 분석: `OPENAI_API_KEY` 환경변수가 있을 때만 OpenAI Responses API를 명시적으로 실행. 홈페이지는 전체 회차, 기사 편집 화면은 현재 분야 검토. 20건 단위 배치, 스키마 및 기사 ID 검증. **메타데이터 기반 제안**이므로 기사 본문 검증을 대체하지 않음.
- GPT 질문 UI는 선택한 1~10건을 대상으로 한 번씩 묻는 기능이며 대화 세션/자동 편집은 없음. API 미설정 시 JSON 수동 분석 경로 유지.
- CLI: `python main.py ai-review <회차ID> --out suggestions.json` (분석 제안 파일 저장), 또는 `--out` 없이 DB에 제안 저장. `OPENAI_MODEL` 지정 가능(미지정 시 `gpt-4.1-mini`).
- 환경설정 화면은 YAML 출처·키워드 **조회 전용**. 기존 `config/sources.yaml`, `config/editorial.yaml` 직접 수정 후 서버 재시작 필요.
- 중요한 한계: 사용자 이름은 로컬에서 직접 입력하며 계정 인증은 미구현. 확정 HTML이 실제 메일 발송 준비 완료를 뜻하지 않음(수신거부·발송 설정·브랜드 이미지 별도 연동 필요). 부문별 사이트 URL 자동 탐색, 진짜 다회차 채팅 메모리, 실사이트/API 키를 통한 실사용 검증은 미구현.
- 자세한 설계·경계는 `docs/WORKFLOW_V04.md` 참고.

## 자료 수집 화면 개선 (v0.4.1)
- 수집 화면에서만 상단의 기존 회차 선택을 감추고, 기간·회차 ID·회차 제목·생성 버튼을 한 카드에 배치했다. 다른 업무 화면의 회차 선택은 유지한다.
- 식약처와 언론사 각각 **전체 선택 ↔ 전체 해제** 토글을 제공한다. 개별 선택도 유지하며 현재 선택 수를 보여준다.
- 상세 수집 로그는 **0건·실패·실제 파싱 오류**일 때만 215px 높이의 세로 스크롤 영역으로 표시한다. 정상적으로 후보를 가져온 부분 수집은 결과 요약에만 표시하고, 전체 누락 검증과 혼동하지 않는다.
- 고급 수집 방식·최대 페이지 설정은 접어서 표시한다. SQLite 및 수집 API의 동작과 뉴스레터 출력·확정 규칙은 변경하지 않았다.
## v0.5 기사 검토 작업대
- 뉴스레터 회차별 후보·수집 기록을 분리하고, 미확인 날짜는 해당 수집 작업이 실제 발견한 기사만 회차에 추가한다.
- 규칙/GPT 분석은 제안으로만 보존. 추천·추가 검토·그 외·수록 목록 대기열에서 기사를 여러 페이지에 걸쳐 선택해 명시적으로 수록/제외한다.
- 선택 기사 상세 패널은 원본·GPT 제안·최종 발행 제목·요약·분야를 분리한다. GPT 요약은 사람이 확인해 복사 및 저장하기 전에는 출력하지 않는다.
- TOP 선택은 기존 기록을 유지하고 새 회차에서 자동 체크하지 않는다. 식약처 필수(`mandatory`) 자료 제외는 계속 금지하되 그 외 관련성 검토는 허용한다.
- 미리보기는 운영자용 안내문을 발송자 콘텐츠와 분리해 표시하고, 892호 원본 템플릿·이메일 호환성 스타일은 유지한다.
- 실제 Windows DB의 208건 관련성, 모든 식약처 게시물 커버리지, OpenAI API 실호출과 발송 검증은 별도 확인해야 한다.

- 기사 목록에서 선택하면 넓은 화면에서는 우측 스티키 상세, 좁은 화면에서는 스크롤 이동 없는 측면 편집 패널을 엽니다. 닫기·Escape·미저장 수정 보호 포함.
